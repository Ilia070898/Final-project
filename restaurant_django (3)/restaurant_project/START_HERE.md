# როგორ გავიგო ეს პროექტი

ეს არის არსებული პროექტის უფრო გასაგებად გადაწერილი ვერსია. ფუნქციები შენარჩუნებულია. მოკლე და ჩახლართული ჩანაწერები ჩანაცვლებულია ჩვეულებრივი ციკლებითა და პირობებით. მეტი ხაზი ყოველთვის მეტ სირთულეს არ ნიშნავს.

## ისწავლე ამ თანმიმდევრობით

1. `menu/urls.py`: მისამართის გვერდით წერია ფუნქცია, რომელიც მას ემსახურება.
2. `menu/views.py`: დაიწყე `catalog`-ით, შემდეგ ნახე `find_product`, `add`, `cart_state` და `register`.
3. `menu/forms.py`: აქ წერია, რა მონაცემს ვიღებთ მომხმარებლისგან და რა ითვლება სწორ მონაცემად.
4. `menu/api.py`: აქ ვუკავშირდებით IT Step-ის სერვერს.
5. `menu/templates/menu/`: გვერდის HTML და Django-ს შაბლონის ჩანაწერები.
6. `menu/static/menu/style.css`: ფერები, ზომები, განლაგება.

## ერთი მაგალითი თავიდან ბოლომდე: კერძის დამატება

მომხმარებელი აჭერს „დამატებას“. HTML ფორმას აქვს მისამართი `/cart/add/1/`: ბოლო რიცხვი კერძის ნომერია. `urls.py` ამ მისამართს უკავშირებს `add` ფუნქციას. Django რიცხვს გადასცემს ფუნქციის `product_id` პარამეტრში.

`add` ეძებს კერძს `find_product`-ით. ეს დამხმარე ფუნქცია ციკლით ათვალიერებს API-დან მიღებულ კერძებს. როდესაც ნომრები ემთხვევა, აბრუნებს კერძს; თუ ვერ იპოვა, აბრუნებს `None`-ს.

შემდეგ `find_basket_item` ამოწმებს, არის თუ არა კერძი კალათაში. თუ არ არის, რაოდენობა იქნება 1. თუ უკვე არის, არსებულ რაოდენობას დაემატება 1. 99-ზე მეტი რაოდენობა უარყოფილია.

`api.write_basket` აგზავნის კერძის ნომერს, რაოდენობას და კატალოგიდან აღებულ ფასს. ახალი ჩანაწერისთვის იყენებს POST-ს, არსებულის შესაცვლელად PUT-ს.

`reply` ინახავს წარმატების ან შეცდომის შეტყობინებას და მომხმარებელს კალათის გვერდზე გადაამისამართებს. ბრაუზერი ითხოვს კალათის გვერდს, Django ახლიდან იღებს კალათის მონაცემებს, ითვლის ჯამს და აბრუნებს HTML-ს. ამ პროექტში JavaScript არ გამოიყენება.

## სინტაქსის მცირე ლექსიკონი

- `def`: ვქმნით ფუნქციას — სახელდებულ მოქმედებას.
- `request`: შეიცავს ბრაუზერიდან მოსულ მოთხოვნას.
- `request.GET`: მისამართით გადაცემული ფილტრები.
- `request.POST`: ფორმით გამოგზავნილი მონაცემები.
- `if / else`: თუ პირობა სრულდება, გააკეთე ერთი რამ; წინააღმდეგ შემთხვევაში — მეორე.
- `for`: თითოეულ ელემენტზე გაიმეორე მოქმედება.
- `return`: დააბრუნე შედეგი და დაასრულე ფუნქცია.
- `None`: მნიშვნელობა არ გვაქვს ან ვერ ვიპოვეთ.
- `[]`: სია; `append` სიაში ამატებს ელემენტს.
- `{}`: ლექსიკონი — სახელისა და მნიშვნელობის წყვილები.
- `product["price"]`: კერძის ლექსიკონიდან ფასის წაკითხვა.
- `try / except`: სცადე მოქმედება; მოსალოდნელი შეცდომისას აჩვენე მართვადი პასუხი.
- `render`: HTML შაბლონს გადასცემს მონაცემებს და ქმნის გვერდის პასუხს.
- `redirect`: ბრაუზერს სხვა მისამართზე გადასვლას სთხოვს.
- `class`: აქ გამოიყენება Django-ს ფორმის აღსაწერად.
- `super().__init__`: ვასრულებთ მშობელი ფორმის საწყის მომზადებას, შემდეგ ვამატებთ ჩვენს პარამეტრებს.
- `form.is_valid()`: ამოწმებს მომხმარებლის შეყვანილ მონაცემებს.
- `form.cleaned_data`: შემოწმებული და დამუშავებული მონაცემები.
- `@require_POST`: ეს ფუნქცია მხოლოდ POST მოთხოვნას იღებს.
- `{% csrf_token %}`: ფორმას ამატებს უსაფრთხოების ტოკენს, რომელსაც Django ამოწმებს.
- `Decimal`: თანხების ზუსტი ათობითი გამოთვლის ტიპი.

## რა უნდა შეგეძლოს ახსნა

- რატომ ვიყენებთ API-ს? დავალება მოითხოვს IT Step-ის სერვისს; იქიდან მოდის კერძები და იქ იმართება კალათა.
- რა ინახება SQLite-ში? მომხმარებლები და Django-ს სესიები. კერძები იქ არ ინახება.
- რატომ არ წერია საკუთარი მომხმარებლის მოდელი? Django-ს მზა მომხმარებლის მოდელი გამოვიყენეთ.
- რატომ გვჭირდება migrate? Django-ს მოდელებისთვის მონაცემთა ბაზაში საჭირო ცხრილები იქმნება/ახლდება.
- როგორ ითვლება ჯამი? თითოეულის ფასი მრავლდება რაოდენობაზე; მიღებული თანხები იკრიბება.
- როგორ იცვლება გვერდი JavaScript-ის გარეშე? HTML ფორმა აგზავნის მოთხოვნას, Django ამუშავებს მას და კალათაზე გადამისამართების შემდეგ ბრაუზერი განახლებულ HTML-ს იღებს.
- რას აკეთებს რეგისტრაცია? ამოწმებს ფორმას, ინახავს მომხმარებელს ჰეშირებული პაროლით და იწყებს ავტორიზებულ სესიას.
- იზოლირებულია კალათა? არა: გარე API-ში მომხმარებლის იდენტიფიკატორი არ არის. ეს შეზღუდვა ანგარიშის დამატებით არ ქრება.
- მუშაობს რეალური შეკვეთა ან გადახდა? არა; ეს პროექტი კერძების არჩევასა და კალათას მოიცავს.

## რას არ სჭირდება ხაზობრივად დაზეპირება

`config` არის პროექტის კონფიგურაცია; უნდა იცოდე პარამეტრების დანიშნულება. CSS განსაზღვრავს დიზაინს; საკმარისი არ არის მისი გამოტოვება, მაგრამ თითოეული ზომის დაზეპირება საჭირო არ არის. `tests` არის შემოწმებები და არა მომხმარებლის მოქმედებების შესრულების კოდი. ლექტორის მოთხოვნის შემთხვევაში მათი დანიშნულებაც ახსენი.

წარდგენისთვის დაიწყე ერთი სრული მოქმედების ჩვენებით და შემდეგ გადადი შემდეგზე. ჩაინიშნე, რომელი ნაწილები გააკეთე დახმარებით, და მიჰყევი კურსის ავტორობის/AI-ის წესებს. ეს გზამკვლევი სწავლისთვისაა და არა იმის მტკიცებისთვის, რომ დახმარება არ გამოგიყენებია.

რაოდენობის ცვლილება მაშინ ინახება, როცა მომხმარებელი ღილაკს „შეცვლა“ აჭერს. მხოლოდ ველში რიცხვის ჩაწერა მოთხოვნას არ აგზავნის.
