# სუფრა — ონლაინ რესტორანი

Python / Django პროექტი ატვირთული საკურსო დავალების მიხედვით.

## გაშვება
საჭიროა Python 3.10 ან უფრო ახალი ვერსია და ინტერნეტი.
გახსენით ტერმინალი ამ საქაღალდეში (იქ, სადაც manage.py არის).

```bash
python -m venv .venv
```
Windows PowerShell:
```powershell
.venv\Scripts\Activate.ps1
```
macOS / Linux:
```bash
source .venv/bin/activate
```
შემდეგ:
```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```
გახსენით http://127.0.0.1:8000/
თუ macOS/Linux-ზე `python` არ არსებობს, გამოიყენეთ `python3`.

## ფუნქციები
- ორი ძირითადი გვერდი: მენიუ `/` და კალათა `/cart/`.
- რვა კატეგორია უშუალოდ API-დან.
- კომბინირებული ფილტრები: კატეგორია, სიცხარე 0–4, თხილეული, ვეგეტარიანული.
- „ყველა“, „კი“, „არა“ ცალკე არჩევანებია; სიცხარე 0 სწორად იგზავნება.
- კერძის სურათი, დასახელება, ფასი და ინგრედიენტების ინდიკატორები.
- დამატება, განმეორებითი დამატებით რაოდენობის გაზრდა, ცვლილება და წაშლა.
- რაოდენობის ფორმის გაგზავნის შემდეგ გვერდის განახლება და ზუსტი Decimal თანხები.
- მხოლოდ Python, Django, HTML და CSS; JavaScript საერთოდ არ გამოიყენება.
- CSRF დაცვა, POST-only ცვლილებები, რაოდენობის ვალიდაცია (1–99).
- API-ის გათიშვის, ცარიელი შედეგისა და ცარიელი კალათის მდგომარეობები.
- ქართულენოვანი, მობილურზე მორგებული ინტერფეისი.

## API
დოკუმენტაცია: https://restaurant.stepprojects.ge/swagger/index.html
სქემა: https://restaurant.stepprojects.ge/swagger/v1/swagger.json

| ოპერაცია | მეთოდი და endpoint |
|---|---|
| კატეგორიები | GET /api/Categories/GetAll |
| კერძები | GET /api/Products/GetAll |
| ფილტრები | GET /api/Products/GetFiltered |
| კალათა | GET /api/Baskets/GetAll |
| დამატება | POST /api/Baskets/AddToBasket |
| რაოდენობა | PUT /api/Baskets/UpdateBasket |
| წაშლა | DELETE /api/Baskets/DeleteProduct/{id} |

კალათის წამკითხველი მხარს უჭერს როგორც რეალურ ჩაშენებულ `product.id` ფორმატს, ასევე Swagger-ის `productId` ფორმატს.

API-ის მართლწერა `vegeterian` განზრახ შენარჩუნებულია.
Django სერვერი უკავშირდება API-ს; ბრაუზერი მუშაობს Django-სთან, ამიტომ CORS-ის კონფიგურაცია საჭირო არ არის.
ფასს სერვერი პროდუქტების კატალოგიდან იღებს და ბრაუზერის მიერ გამოგზავნილ ფასს არ ენდობა.
₾ არის ინტერფეისისთვის არჩეული ვალუტა: API ცალკე currency ველს არ იძლევა და კონვერტაცია არ ხდება.

**შეზღუდვა:** API-ის კალათის ენდპოინტებს მომხმარებლის ან სესიის იდენტიფიკატორი არ აქვთ. კალათა შესაძლოა საერთო იყოს სხვა სტუდენტებთან. ეს არის დავალების API-ს ინტეგრაცია და არა იზოლირებული კომერციული კალათა. ერთდროული ცვლილებების ატომურ გარანტიას API არ იძლევა. საჯარო API-ზე ტესტური ჩაწერები არ გაკეთებულა. რეალური გადახდა/checkout დავალებაში არ არის და პროექტი არ აგზავნის რეალურ შეკვეთას.

სურათები იტვირთება API-ში მითითებული გარე მისამართებიდან. ინტერნეტის გარეშე მენიუ ვერ ჩაიტვირთება. მოთხოვნას აქვს 12-წამიანი timeout; წარუმატებელი ჩაწერა ავტომატურად არ მეორდება, რადგან შეიძლება სერვერზე უკვე შესრულებული იყოს. ასეთ დროს ჯერ განაახლეთ კალათა.

## სტრუქტურა
- `config/` — Django კონფიგურაცია, URL-ები და WSGI.
- `menu/api.py` — გარე REST API, JSON და Decimal ფასები.
- `menu/forms.py` — ფილტრებისა და რაოდენობის ვალიდაცია.
- `menu/views.py` — გვერდები, კალათის მოქმედებები, JSON პასუხები.
- `menu/templates/menu/` — HTML შაბლონები.
- `menu/static/menu/` — CSS სტილები.
- `menu/tests/` — იზოლირებული ავტომატური ტესტები.

კერძები და კალათა გარე API-ში ინახება, ამიტომ მათი დუბლირებული Django მოდელები არ არის. SQLite გამოიყენება Django-ს სესიებისთვის/შეტყობინებებისთვის. ადმინისტრატორის ანგარიში საჭირო არ არის.

## გარემოს პარამეტრები
ნაგულისხმევი პარამეტრები ლოკალური სასწავლო გაშვებისთვისაა. `.env` ავტომატურად არ იკითხება; ცვლადები დააყენეთ ტერმინალში ან ჰოსტინგზე.
- `DJANGO_DEBUG`: `1` ლოკალურად, `0` განთავსებისას.
- `DJANGO_SECRET_KEY`: საკუთარი საიდუმლო მნიშვნელობა; სავალდებულოა DEBUG=0 რეჟიმში.
- `DJANGO_ALLOWED_HOSTS`: მძიმით გამოყოფილი დომენები.
- `RESTAURANT_API_URL`: API-ის ბაზა, ნაგულისხმევად `https://restaurant.stepprojects.ge/api`.

საჯარო განთავსებას სჭირდება HTTPS, WSGI სერვერი, static ფაილების მომსახურება (`python manage.py collectstatic`) და ჰოსტინგის შესაბამისი უსაფრთხოების კონფიგურაცია. `runserver` არის მხოლოდ დეველოპმენტისთვის.


## რეგისტრაცია და ავტორიზაცია
- `/register/` — სახელი, მომხმარებლის სახელი, ელფოსტა და პაროლის გამეორება.
- `/login/` — შესვლა მომხმარებლის სახელითა და პაროლით.
- `/logout/` — POST ფორმით უსაფრთხო გამოსვლა.
- წარმატებული რეგისტრაცია ავტომატურად შედის ანგარიშში.
- ანგარიშები ინახება ლოკალურ SQLite-ში, პაროლები — Django-ს ჰეშირებით.
- მუშაობს Django-ს პაროლის ვალიდაცია და მომხმარებლის სახელის უნიკალურობა.
- ელფოსტა ინახება, თუმცა დამადასტურებელი წერილი არ იგზავნება; შესვლა ხდება მომხმარებლის სახელით.
- მენიუ და კალათა სტუმრებისთვისაც ხელმისაწვდომია. ანგარიშის დამატება არ ცვლის გარე სასწავლო API-ის საერთო კალათის ქცევას.

### ძველი ვერსიის განახლება
გააჩერეთ სერვერი Ctrl+C-ით. ახალი არქივიდან გადააკოპირეთ პროექტის ფაილები ძველ `restaurant_project` საქაღალდეში. შეინარჩუნეთ არსებული `.venv` და `db.sqlite3` (არქივი მათ არ შეიცავს). შემდეგ გააქტიურებულ გარემოში გაუშვით:
```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```
`migrate` აუცილებელია მომხმარებლების ცხრილების შესაქმნელად.
